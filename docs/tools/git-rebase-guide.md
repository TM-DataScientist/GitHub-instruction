# Git リベース (rebase) ガイド
作成日: 2026-05-08

## 1. Git リベースとは？
Git における「リベース (rebase)」とは、あるブランチの変更点を別のブランチの先端に「再適用」する操作のことです。
基本的には、あるブランチ（例：トピックブランチ）の「基点（ベース）」を、別のブランチ（例：mainブランチ）の最新のコミットに移動させることを意味します。

## 2. リベースのメリット
- **履歴が一直線になる**: マージコミット（Merge branch 'xxx' into 'yyy'）が発生しないため、コミットログが綺麗で読みやすくなります。
- **プロジェクト履歴の整理**: 開発途中の細かな修正コミットをまとめたり（squash）、コミットメッセージを修正したりする際にも利用されます。

## 3. マージ (merge) との違い
- **マージ**: 2つのブランチの最終状態（スナップショット）を統合します。履歴には分岐と合流の跡が残ります。
- **リベース**: ブランチの変更内容（パッチ）を1つずつ対象ブランチの先端に適用し直します。履歴が1つの線になります。

## 4. ⚠️ 重要な注意点（黄金律）
**「公開されている（リモートリポジトリにプッシュ済みの）コミットはリベースしてはいけない」**
リベースは歴史を書き換える操作です。他人がすでに取得しているコミットをリベースして歴史を変えてしまうと、整合性が取れなくなり、共同開発に大きな混乱を招きます。
